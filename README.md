# caddy-http-acme

A minimal Caddy DNS provider for ACME DNS-01 services which expose an HTTP API.

The provider intentionally has a tiny scope: when Caddy asks it to publish a TXT
challenge, it expands runtime placeholders in `params` and sends one HTTP request.
Cleanup is a no-op in the PoC because services such as myaddr.tools automatically
expire their ACME TXT values.

## Example: myaddr.tools

```caddyfile
yourname.myaddr.tools {
    tls {
        dns http_acme {
            endpoint https://myaddr.tools/update
            method POST
            body json

            params {
                key {$MYADDR_KEY}
                acme_challenge {challenge}
            }
            
            result {
                success_code 200 # or "2xx" for any 2xx code
                success_body "OK" # shorthand for contains "OK"
            }
        }
    }
}
```

Runtime placeholders supported by the PoC:

- `{challenge}` — the TXT value generated by ACME
- `{domain}` — the domain Caddy is challenging

`body` may be `query`, `form`, or `json`.

`result` is optional. By default, any `2xx` response succeeds. Configure
`success_code` with an exact HTTP status code or `2xx`, and configure
`success_body` with text that must occur in the response body. All configured
result conditions must match. `success_body` uses substring matching; regex
matching is planned for v0.2.

The module ID is `dns.providers.http_acme`.

This provider is intended for an ACME DNS challenge configuration. It
implements the libdns append and delete operations required by Caddy's ACME
solver, but not the complete set of operations required by Caddy's global DNS
provider configuration. Cleanup is a no-op because myaddr.tools expires ACME
challenge values automatically and does not document an API to delete one
value.
